Сервер 0.4 поддерживает формы заказов и финансов, роли на изменение разделов и журнал. Ниже сохранено описание ранних версий; ограничения сервера 0.3 заменены разделом релиза 0.4.

# Nasha Volna AI

Статический MVP. `index.html` загружает `task-core.js` и `app.js`; данные и контекст
диалога сохраняются в `localStorage` под прежним ключом `nv_mvp_v2`.
По умолчанию работает локальный режим. Добавлен серверный режим: интерфейс подключения,
адаптер модели, постоянная база и планы действий. Для активации нужен отдельный
запущенный сервер и доступ к модели; см. [server/README.md](server/README.md).
Python-пакет `core/` — прежний прототип; новый HTTP-сервис находится в `server/`.
Python не исполняется на GitHub Pages.

## Задачи через чат

1. `Создай задачу: Проверить MVP на завтра`
2. `Переименуй её в Проверить отчёт`
3. `Перенеси её на 30.09.2026`
4. `Покажи задачи`
5. `Заверши её`

Также: `Возьми в работу задачу Проверить отчёт`, `Возобнови её`,
`Найди задачу отчёт`, `Покажи активные задачи`, `Покажи выполненные задачи`.
«Её» относится к последней созданной, выбранной или изменённой задаче.
Если совпадений несколько, укажите номер из предложенного списка или точное
название. `Отмена` отменяет ожидающее уточнение, но не откатывает уже выполненные действия.
Если команда создания не содержит названия, ядро спрашивает его следующим сообщением.

Сроки: сегодня/завтра/послезавтра (по Москве), ДД.ММ.ГГГГ или ГГГГ-ММ-ДД.
Название активной задачи проверяется на дубликат. Произвольный разговор и сложные
составные поручения не поддерживаются: это локальный обработчик команд, не LLM.
Данные сохраняются только в этом браузере; очистка данных сайта удаляет их.
При ошибке записи команды чата откатываются и показывают ошибку вместо успеха.

## Проверка

```sh
node --test tests/*.test.cjs
python -m unittest discover -s core/tests
python -m unittest discover -s server/tests
python -m http.server 8765
```

Откройте http://localhost:8765. После создания/изменения задачи обновите страницу
и проверьте раздел «Задачи». На телефоне разделы доступны в горизонтальном меню.

## Рабочий обзор и проекты

Раздел «Обзор» показывает активные задачи, просрочки, сроки на сегодня и задачи
без корректного срока. Клик по числу открывает соответствующий фильтр.
Карточка проекта показывает прогресс только по явно привязанным задачам.
Локальные формы позволяют создавать проекты, создавать/редактировать задачи,
задавать и очищать срок, привязывать задачу к проекту и менять статус.
При ошибке записи изменения форм откатываются. Прежние данные не мигрируются
автоматически в проекты: привязку выбирает пользователь.

Без модели работают команды:

- `План на сегодня` — до пяти задач: просроченные, со сроком сегодня, уже в работе,
  с ближайшим сроком, без срока. Это очередь, не оценка загрузки дня.
- `Покажи просроченные задачи`.
- `Обзор проекта Nasha Volna` — только связанные задачи и указанные сроки.
- `Найди в документах доставка` — совпадения по словам/частям слов, с выдержкой
  и id источника. Поддержано простое совпадение русских окончаний; это не
  семантический поиск и не полноценная морфология.

Все даты обзора считаются по Москве. Выполненные задачи не считаются просроченными.
Неизвестные зависимости, трудозатраты и причины задержки не выдумываются.
В серверном режиме обзор читает загруженный снимок; свежие данные загружаются
кнопкой «Обновить» в чате. Изменения по-прежнему через серверный план.

### Локальные данные и навигация

- Единый SVG-набор, доступная с клавиатуры навигация и общий поиск (кнопка в шапке или Ctrl/Cmd K). Поиск буквальный, по всем словам, до 100 результатов; включает задачи, проекты, память, клиентов и текст документов.
- Раздел «Данные»: JSON-копия записей и переписки, предварительная проверка импорта, явная замена данных, отмена одного последнего сохранения и 30 событий локальной истории. Это не неизменяемый журнал аудита. Ключи доступа не экспортируются.
- Все локальные записи сохраняются с откатом при ошибке. Последовательные записи из устаревшей вкладки отклоняются; localStorage не даёт транзакционной блокировки для абсолютно одновременных записей. Для многопользовательской работы нужен сервер.
- Повреждённый JSON блокирует изменения и доступен для скачивания без перезаписи. Импорт ограничен 5 МБ; история хранит один предыдущий снимок и поэтому увеличивает объём localStorage. Регулярно скачивайте копию: очистка браузера удаляет локальное пространство.
- В серверном режиме локальная отмена/импорт заблокированы; экспорт скачивает сохранённое локальное пространство. Серверные данные требуют отдельного резервного копирования SQLite.

### Клиенты → заказы → задачи

Локальные карточки клиентов содержат контакты, заметки и список заказов. Заказ хранит стоимость в рублях (до копеек), этап, срок, текстового ответственного, описание и необязательную ссылку на проект. Задачи можно создавать из заказа или привязывать в редакторе. Статус заказа не меняет статусы задач автоматически; сумма активных заказов не является выручкой или прибылью.

Удаление клиента с заказами и заказа с задачами блокируется. Сохранение/удаление поддерживает существующую отмену последнего действия. Поиск включает заказы и заметки клиентов. Копии теперь версии 2; импорт версии 1 поддерживается с пустым списком заказов. Серверный API пока не поддерживает заказы, поэтому импорт локального пространства с заказами на сервер заблокирован, чтобы не потерять связи. Подключение и отключение сервера сохраняет локальные записи.

### Финансы и документы (локальный режим)

«Финансы» — ручной управленческий учёт фактически совершённых операций в RUB. Поступления и возвраты обязательны к заказу; расходы могут быть общими. Перед сохранением есть просмотр и подтверждение. Суммы вычисляются в целых копейках. Исправление создаёт обратную запись сегодняшней датой, исходная запись остаётся. В отдельном периоде результат исправлений может быть отрицательным. Это не неизменяемый бухгалтерский журнал: локальная отмена/импорт и доступ к браузеру позволяют изменять состояние.

Денежный результат = поступления − возвраты − расходы. Осталось получить = max(0, стоимость заказа − поступления + возвраты); для заказов без стоимости и отменённых заказов показатель не рассчитывается. Срок выполнения заказа не считается сроком оплаты. Переплата показывается отдельно. Данные не синхронизируются с банком, платежи не исполняются, налоги/начисления/себестоимость незавершённых работ не рассчитываются. Поэтому показатели не называются бухгалтерской прибылью или просроченной задолженностью.

Есть фильтры операций по датам/заказу и CSV-экспорт (UTF-8 BOM, разделитель `;`, экранирование формул и кавычек). «Финансовый обзор», «Сколько нам должны» и «Экономика заказа <название или ID>» в локальном AI дают детерминированный расчёт с источниками; изменение финансов через чат не разрешено. Общие расходы не распределяются между заказами автоматически.

Документы теперь можно редактировать в форме, указывать папку, проект и заказ. Текст рендерится с экранированием HTML. Удаление заказа с операциями или документами блокируется. Резервные копии версии 3 включают операции и их связи; версии 1/2 мигрируют без финансов. Импорт проверяет даты, суммы, категории, внешние ссылки и однократность исправлений. Конкурирующие чтения выбранных файлов не подменяют последнюю копию.

Добавлена CSP: скрипты/стили только со своего origin, запрет объектов, смены base URI и отправки HTML-форм; API-соединения допускаются по HTTPS и на localhost для разработки. CSP не заменяет серверную авторизацию, шифрование хранения или аудит безопасности. Копии JSON и CSV не шифруются. Серверный импорт отклоняет неподдерживаемые заказы/финансы целиком, сохраняя старое состояние. Серверная часть этого изменения требует отдельного развёртывания администратором.
