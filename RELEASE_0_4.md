# ERP 0.4 — операционный контур

Релиз от 29 сентября 2026 года.

## Работающие новые разделы

- Команда: карточки сотрудников, контакты, должность, активность, количество назначенных заказов и задач.
- Каталог: товар, уникальный артикул, единица измерения и минимальный запас.
- Склад: один склад, приходы и списания, точные количества до трёх десятичных знаков, запрет отрицательного остатка, журнал движений.
- Закупки: заказ товара у указанного поставщика, дата поставки, отмена и полная приёмка. Приёмка увеличивает остаток один раз.
- Заказы и задачи: назначение сотрудника по ID. У заказа отдельная дата оплаты. Финансы показывают просроченный остаток по дате оплаты.
- Копия версии 4 включает товары, движения и закупки. Старые версии 1–3 поддерживаются.

## Серверный контур

Версия сервера 0.4 добавляет `/api/records` для форм. Клиенты, заказы, задачи, проекты, документы, сотрудники, финансы, каталог, склад и закупки сохраняются одним проверяемым пакетом без вызова AI. Пакет проходит серверную проверку связей, дат, сумм и остатков. При ошибке откатывается целиком. Ревизия пространства защищает от устаревшего сохранения, request ID — от повторного исполнения.

Финансовые и складские записи через API не изменяются и не удаляются. Финансовая корректировка создаёт обратную запись, складская — новое движение. Приёмка закупки и приход проводятся одной транзакцией. Товарам с движениями нельзя менять единицу измерения.

`GET /api/audit` показывает владельцу последние 100 серверных событий, автора запроса и изменения до/после. Это журнал в SQLite, не криптографически неизменяемое хранилище. Администратор базы может изменить его.

Роли ограничивают **изменение разделов**. Все роли пока читают весь снимок своей компании. Права на отдельные записи и поля, полноценные аккаунты, приглашения, пароли, 2FA и отзыв сессий в этот релиз не входят. Карточка сотрудника сама по себе не создаёт доступ и не определяет роль ключа.

Администратор может задавать существующую строковую конфигурацию `ключ → пространство` (роль владельца) или объект `ключ → {workspace, actor, role}`. Допустимые роли: owner, manager, accountant, member, viewer. Использовать отдельный случайный ключ не короче 32 символов для каждого пользователя. `actor` должен быть стабильным уникальным именем пользователя. Отзыв доступа — удалить ключ из конфигурации и перезапустить сервис.

| Роль | Разрешённые изменения |
|---|---|
| owner | Все разделы, импорт, применение AI-планов |
| manager | Клиенты, заказы, задачи, проекты, документы, память, товары, закупки, склад |
| accountant | Финансовые записи и документы |
| member | Задачи и документы |
| viewer | Только чтение |

AI-чат и применение AI-планов в 0.4 доступны только владельцу. Настройка модели не требуется для ручной работы с формами. История запросов и audit пока не очищаются автоматически. Сервис рассчитан на один процесс и небольшую нагрузку. База хранит снимок JSON в SQLite; PostgreSQL и нормализованные таблицы ещё не реализованы.

## Подключение и миграция

1. Сделать копию базы SQLite перед обновлением. Локальные данные сохранить через «Данные → Скачать копию».
2. Обновить сервер и перезапустить с прежней конфигурацией. Чтение старых пространств добавляет пустые новые коллекции, существующие записи сохраняются.
3. На сайте подключиться к своему HTTPS-серверу. Для разработки разрешён localhost.
4. Импортировать локальные записи в пустое серверное пространство. Заказы, финансы и связи теперь поддерживаются. История локального AI-чата не переносится как доверенный контекст модели.
5. Проверить количество записей, связи, суммы и остатки. После подключения формы сохраняют серверные данные, локальная копия не перезаписывается.

Ключ хранится в памяти вкладки. После обновления страницы подключение нужно повторить. Нет автоматического слияния локальной и серверной базы. В серверном режиме JSON-копия выгружает текущий снимок; она не заменяет резервную копию самой базы, запросов и журнала.

## Проверка

`node --test tests/*.test.cjs`

`python3 -m unittest discover -s server/tests`

`python3 -m unittest discover -s core/tests`

Дополнительные проверки покрывают повторную приёмку, отрицательный склад, неизменность финансовых записей, одинарное исправление, права на API, конфликт ревизий, восстановление после перезапуска и сохранение связей импорта.

Публичный интерфейс работает на GitHub Pages. Python-сервер отдельно не развёрнут этим релизом: хостинг Pages его не исполняет. Поэтому общая многопользовательская база заработает только после запуска отдельного сервера. На опубликованном интерфейсе новые разделы доступны локально без входа.

Это начало реализации ERP, а не готовность всех 200 пунктов: бухгалтерия, MRP, payroll, сложная WMS, интеграции и marketplace требуют следующих релизов.
