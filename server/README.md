# Nasha Volna server core v0.3

## Что реализовано

- Python 3.11+, стандартная библиотека, SQLite на постоянном диске.
- Адаптер OpenAI Responses API с принудительным структурированным ответом.
- История разговоров, факты/предпочтения, задачи, проекты, клиенты и текстовые документы.
- Контекст выбирается по совпадениям слов. Это не embeddings/RAG по PDF: принимается текст.
- Ответы могут ссылаться на реальные IDs записей; неизвестные источники отклоняются.
- Модель предлагает до 20 действий, ядро проверяет план целиком, пользователь видит поля изменений.
- Подтверждение плана применяет всё одной транзакцией. Устаревшие планы отклоняются.
- Идемпотентные запросы, ревизии, журнал применения, изоляция рабочих пространств.

**Статус:** реализация и автоматические проверки готовы. Публичный сервер и реальный
провайдер модели не были подключены в этой среде. Тесты используют FakeProvider и
подменённый HTTP-ответ API; они не доказывают качество ответов реальной модели.
GitHub Pages размещает только интерфейс и не исполняет этот Python-сервер.

## Настройки сервера

Перед запуском администратор задаёт секреты через окружение/секрет-хранилище хостинга.
Не добавлять значения в GitHub, HTML, JavaScript, снимки экрана или журналы.

| Переменная | Назначение |
|---|---|
| `OPENAI_API_KEY` | Действующий ключ модели; только на сервере. Для безопасного выпуска нужен соответствующий защищённый процесс настройки. |
| `OPENAI_MODEL` | Доступная вашему API-проекту модель с Responses/function calling. Без значения модель не считается настроенной. |
| `NV_ACCESS_TOKENS` | JSON-объект: случайный ключ доступа длиной от 32 символов → стабильное имя рабочего пространства. Два ключа с одним именем открывают одни данные. |
| `NV_ALLOWED_ORIGINS` | Точные адреса интерфейса через запятую; по умолчанию `https://frostphonk1488-lang.github.io`. Для локальной разработки добавить `http://localhost:8765`. |
| `NV_DATABASE` | Постоянный путь SQLite. По умолчанию `data/nasha-volna.sqlite3`. |
| `NV_BIND`, `PORT` | По умолчанию `127.0.0.1:8080`. В контейнере `0.0.0.0:8080`. |

Ключ рабочего пространства — отдельный случайный секрет, не API-ключ OpenAI.
Администратор может получить его через `secrets.token_urlsafe(32)` в защищённой среде
и передать владельцу по безопасному каналу. Ротация ключа при сохранении имени
рабочего пространства не теряет данные. Этот MVP имеет одну роль владельца;
полноценные аккаунты, приглашения и права сотрудников ещё не реализованы.

Запуск после настройки окружения:

```sh
python -m server.http
```

Для контейнера: `docker build -t nasha-volna-core .`, затем запуск с переменными
окружения и постоянным томом `/data`. Поставьте HTTPS reverse proxy перед портом
8080. API не раздаёт файлы репозитория. Не публикуйте порт в HTTP без TLS.
Один процесс сериализует обращения к базе; это MVP для небольшой нагрузки, не
горизонтально масштабируемый production-сервис. Резервное копирование SQLite,
лимиты затрат у поставщика и ротация ключей управляются администратором.
Сервер ограничивает chat до 10 запросов за минуту на рабочее пространство.

## Подключение сайта

1. На сайте откройте «Подключить AI».
2. Введите HTTPS-адрес **своего** сервера и ключ рабочего пространства.
3. Ключ хранится только в памяти вкладки. После обновления страницы введите его снова.
4. Через «Подключение» можно импортировать локальные записи в пустую серверную базу.
   Операция сохраняет IDs и связи, не стирает локальные записи и не импортирует
   локальные сообщения как доверенную историю модели.
5. Напишите: «Создай проект Запуск и задачи Подготовить текст и Проверить сайт».
6. Проверьте карточку плана и примените её. После этого новые записи видны в разделах.

В серверном режиме ручные кнопки редактирования списков отключены: изменения
проходят через чат и проверку плана. «Обновить» загружает изменения с другого
устройства. При отключении серверного режима восстанавливается локальная копия.
Данные устройств не объединяются автоматически. Импорт доступен только один раз
в пустое пространство; при конфликте ревизий обновите данные и повторите команду.
Любое новое сообщение делает предыдущий неподтверждённый план устаревшим.

Поддерживаются: task.create/update, memory.save/update/delete, project.create,
client.create, document.create. В связанных новых задачах используется projectName;
для существующих записей — точный ID. Удаления проектов/задач и выполнения
внешних операций нет. Напоминания и фоновые задания пока не реализованы.
Документы до 20 000 символов, сообщения до 6 000, до 500 записей на раздел.
Контекст ограничен по размеру и помечается усечённым, если не все записи переданы.

## API

Все `/api/*` требуют `Authorization: Bearer <ключ рабочего пространства>`.
`GET /health` сообщает только доступность сервиса. `GET /api/state` возвращает
серверные данные, ревизию, активные планы и наличие настроек модели.

POST-запросы содержат `requestId` (уникальный ID) и `revision` (текущая ревизия):

- `/api/chat`: `message`.
- `/api/import`: `data` с коллекциями из браузера.
- `/api/plans/<id>/confirm` и `/api/plans/<id>/cancel`.

При потере ответа повторите **тот же запрос с тем же ID**, чтобы не дублировать
операцию. Нельзя повторно использовать ID для другого тела. Ошибка 409 требует
обновить состояние. Нет ответа не означает, что действие не выполнено.
План действует час. Не храните журнал запросов бесконечно: в MVP автоматическая
очистка audit/requests не добавлена.

## Проверки

```sh
python -m unittest discover -s server/tests -v
python -m unittest discover -s core/tests
node --test tests/*.test.cjs
```

После настройки действующего API требуется smoke-test реальной модели: обычный
вопрос → ответ, проект + задачи → план → подтверждение, запрос по документу →
источник, перезапуск → восстановление данных. Следует оценить точность на своих
примерах: валидация структуры не гарантирует правильную интерпретацию поручений.

Официальная документация адаптера:
https://developers.openai.com/api/docs/guides/function-calling
