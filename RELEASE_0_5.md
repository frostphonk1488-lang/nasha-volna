# AI-ядро Nasha Volna 0.5

Это собственный слой управления ассистентом: поиск, контекст, точные расчёты,
проверка действий, подтверждение, сохранение истории и аудит. Нейросетевые веса
не обучены нами. Для свободного разговора нужен отдельный движок модели:
OpenAI API или локальная модель через Ollama. GitHub Pages размещает интерфейс;
Python-ядро и SQLite запускаются отдельно, в том числе на домашнем ПК.

## Что изменилось

- Лексический поиск с BM25 и консервативным сопоставлением русских окончаний.
  Это не embeddings и не гарантия понимания смысла. Документы разбиваются на
  перекрывающиеся фрагменты по 1600 символов: поиск видит весь текст, в ответ
  попадает лучший фрагмент с его смещением. PDF/OCR пока нет.
- К связанным найденным записям добавляются клиенты, проекты, заказы, товары и
  сотрудники по ID. Контекст ограничен: 80 записей, 40 тыс. символов записей
  для внешней модели и 16 тыс. для Ollama. Ограничение не включает небольшой
  блок метрик, счётчиков и до 8 тыс. символов истории.
- Для вопросов с местоимениями поиск учитывает последние два сообщения
  пользователя. Это эвристика, неоднозначный вопрос всё ещё требует уточнения.
- До восьми сохранённых предпочтений включаются в контекст. Новые факты памяти
  записываются через подтверждённый план; ядро не обучает веса на разговорах.
- Метрики рассчитываются по полному снимку компании. Деньги — целые копейки,
  склад — тысячные единицы. Возвраты, обратные записи и отдельная дата оплаты
  учитываются; денежный результат не называется бухгалтерской прибылью.
- Изменение существующей задачи/памяти возможно только по ID, присутствующему
  в контексте модели. Ссылки проекта тоже проверяются; создание проекта и его
  задач в одном плане поддерживается. Изменение памяти требует прямой просьбы
  в текущем сообщении. Проверка всего плана и подтверждение остаются обязательными.
- Журнал `ai.responded` содержит режим обработки, число найденных записей,
  источники и число предложенных действий, без нового копирования текста чата.
- `GET /api/state` сообщает версию ядра, выбранный движок и наличие настроек
  модели. Наличие настроек не доказывает доступность или качество модели.

## Команды без языковой модели

На подключённом сервере:

| Команда | Результат |
|---|---|
| `Финансовый обзор` | Поступления, возвраты, расходы, денежный результат, остаток оплаты и просрочка |
| `Рабочий обзор` / `Какие у меня задачи?` | Активные задачи, сроки, число просроченных |
| `План на сегодня` | Существующие незавершённые задачи со сроком сегодня или раньше |
| `Складской обзор` / `Что заканчивается на складе?` | Товары ниже минимального остатка |
| `Что ты помнишь?` | Последние сохранённые записи памяти |
| `Найди гарантия` | Лексический поиск по данным компании |

Команды распознаются по указанным формам, без свободного понимания языка.
Ничего не изменяют и не обращаются к модели. Остальные вопросы отправляются
выбранной модели; если она не настроена, возвращается явная ошибка.

## Модель на Windows через Ollama

1. Установить Ollama с https://ollama.com/download/windows.
2. Скачать подходящую локальную модель отдельно. Название взять из `ollama list`.
   Конкретная модель зависит от RAM, видеокарты, VRAM и желаемой скорости.
3. Для полностью локального вывода отключить облачные функции Ollama. Остановить
   уже работающий Ollama перед запуском отдельного процесса в PowerShell:

```powershell
$env:OLLAMA_NO_CLOUD = "1"
ollama serve
```

Переменная должна быть задана именно процессу Ollama. Подключение к loopback
само по себе не доказывает, что выбранная модель не использует облако.

4. В другом PowerShell, в папке проекта, с уже настроенными ключами пространства
   и путём SQLite из предыдущей инструкции:

```powershell
$env:NV_AI_PROVIDER = "ollama"
$env:NV_LOCAL_MODEL = "НАЗВАНИЕ_ИЗ_OLLAMA_LIST"
py -m server.http
```

5. Подключить сайт к HTTPS-адресу своего Python-сервера и ключу пространства.
   Туннель направлять на порт 8080 Python-сервера. Ollama на 11434 наружу не открывать.

Движок обращается только к loopback `/api/chat`, передаёт JSON Schema,
проверяет завершённость ответа и не переключается автоматически на внешний API.
Модель сама не скачивается. Тайм-аут запроса 40 секунд: на слабом ПК или при
холодной загрузке тяжёлой модели разговор может не успеть завершиться. Следует
сначала прогреть модель локальным запросом и выбрать подходящий размер.

Для внешнего движка: `NV_AI_PROVIDER=openai`, `OPENAI_MODEL`, `OPENAI_API_KEY`.
По умолчанию сохранена совместимость с существующей конфигурацией OpenAI.

## Проверки и границы

32 серверных теста: поиск в конце документа, связанные записи, ограничение
контекста, продолжение разговора, изоляция пространств, расчёты, запрет изменения
невидимой записи, сводки без модели, повтор запроса и протокол Ollama. Также
проходят 8 JavaScript-файлов проверок существующего интерфейса.

Реальная локальная модель не запущена в среде разработки. Её качество, скорость,
устойчивость к внедрённым инструкциям и доступность проверяются отдельно на ПК.
Проверка источника удостоверяет существование ID, но не доказывает, что каждое
утверждение языковой модели соответствует тексту источника.

Ядро рассчитано на один процесс и небольшую нагрузку; запрос модели пока удерживает
общую блокировку сервиса. Нет обучения собственной фундаментальной модели,
фоновых агентов, браузинга, банковских платежей, исполнения кода и самостоятельных
сообщений людям. Авторизация по токенам, сроки планов и резервные копии SQLite
из версии 0.4 остаются актуальными.

Официальные описания протокола и локального режима:
https://docs.ollama.com/capabilities/structured-outputs
https://docs.ollama.com/faq
